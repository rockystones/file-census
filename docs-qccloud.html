qccloud.py — how it works, and how it is safe

One Python file (standard library only) that censuses a OneDrive from the cloud side via Microsoft Graph, into the same SQLite catalog schema the local tools use. The local filesystem is never touched — so placeholder hydration cannot occur — and no file content is ever downloaded. Its unique contribution: every file arrives with a service-computed hash (quickXorHash), giving content-grade duplicate detection with zero bytes read. Output opens in qcview, diffs scan-vs-scan, and feeds the same analyses as any disk census.

1 · The building blocks

PieceWhat it does for qccloud.py
urllib.request The whole HTTP layer — no third-party dependencies to trust. Exactly two request shapes exist: form-encoded POSTs to login.microsoftonline.com (the optional device-code sign-in only), and GETs with a bearer header to graph.microsoft.com. TLS certificate verification is Python's default — no custom SSL context exists anywhere in the file to weaken it.
Graph: /me/drive One call for identity and capacity: the drive's stable id (recorded as the catalog's volume serial), driveType (personal/business), owner, and the quota block (plan size, used, remaining — the cloud analog of disk total/free). Note quota.used includes document version history, so it normally exceeds the visible file tree's byte sum.
Graph: /root/delta The enumeration engine — the same feed sync clients use. It returns every item in the drive as a flat, arbitrarily-ordered stream of pages: follow @odata.nextLink until a final @odata.deltaLink appears. That last link is a resume cursor: stored in the catalog, it makes a future re-census incremental (changes only). The $select trims each item to exactly the census fields — and deliberately excludes downloadUrl, so no response ever contains a pre-authenticated link to file content.
quickXorHash OneDrive's content hash, computed by Microsoft's servers as files are stored, and returned inline as metadata (file.hashes.quickXorHash). This is the piece no local metadata scan can match: proof-grade content identity for hundreds of thousands of files without reading one byte. It lands in the catalog's entry.hash column (local scans leave it NULL). To compare against a local file, compute quickXorHash on that local file — a cheap local read, still no downloads.
json + base64 Response parsing, plus one local trick: describe_token() decodes the middle segment of the JWT locally to show who the token belongs to, its scopes, and minutes to expiry. Nothing is sent anywhere for this, and the token itself is never printed — only those derived claims.
getpass Hidden interactive token entry for --paste-token: the pasted credential is not echoed, so it never lands in the console scrollback buffer.
imported from qc.py open_db (shared schema + migrations), write_summary (the same .txt report), suggest_db_name, human, parse_sort — a cloud census is a first-class catalog, not a special case.

2 · What it defines, and how the values move

Getting a token — three doors, one holder

FunctionPurpose and data in/out
TokenProvider The single place a credential lives: one string held in process memory, plus a renew() hook invoked when Graph answers 401 (tokens live ~1 hour). Renewal that returns the same stale token is treated as failure — no infinite 401 loop.
--token-file / --paste-token The "borrowed token" doors, built for tenants that block app registrations but allow Graph Explorer: you copy the token Graph Explorer already holds and hand it over — from a file the tool only ever reads, or via hidden paste. On expiry you're prompted for a fresh one and the crawl resumes in place.
device_code_signin(tenant, client_id) The self-service door: OAuth device-code flow. Prints a URL + short code, you sign in on Microsoft's page (the tool never sees a password), it polls the token endpoint until approved. Scope requested: Files.Read only, with no offline_access — so no refresh token ever exists to leak. Requires a client id the tenant accepts (your own registration, since Microsoft's first-party CLI id is unavailable to personal accounts and uninstalled in some org tenants).
_signin_guidance(...) Translates raw AADSTS sign-in errors into the next thing to try — the rules were learned from real failures: device codes need a concrete tenant (consumers or a named domain; common/organizations always fail with 50059), personal accounts always need your own app (700016 in the MSA directory), a work 700016 means the tenant resolved and only the client is missing, and 7000218 means the registration forgot "Allow public client flows".
describe_token(token) Local JWT peek printed at startup: token for you@pitt.edu (scopes: …, expires in ~58 min). Unit-tested to never contain the token string itself.

Crawling and building — a flat feed becomes a tree

FunctionPurpose and data in/out
fetch_json(url, provider) The only authenticated request path. Refuses non-Graph URLs before building a request (so even a tampered next-link could not redirect the token), honors Retry-After on 429/503/504 with bounded retries, and on 401 renews and retries the same URL — which is what lets a multi-hour crawl outlive its one-hour tokens without losing its place.
crawl(provider) One /me/drive call, then the delta loop: follow nextLink, stop at deltaLink. Each page is compacted on arrival to a ~300-byte record (id, parent, name, kind, size, times, hash) and the raw ~2 KB Graph dicts are dropped — holding them all was a real MemoryError at 691k items. Records are keyed by id, so a delta feed that mentions an item twice keeps the last occurrence, as the Graph contract specifies. Returns (drive info, records by id, resume cursor); progress prints a running count.
build_catalog(con, drive, items, deltaLink) The flat feed arrives in arbitrary order, so the tree is built by identifiers, not sequence: group children by parent id, anchor on the one item carrying the root facet, then walk top-down assigning entry ids and depths, flushing rows to SQLite every 5,000 (constant memory; a 700k-item build takes seconds). OneNote notebooks are package items — containers without a folder facet — and are walked like folders. Items whose parent never appears, or whose parent is not a container, attach under the root with a printed note rather than being dropped. Files carry size, timestamps (fileSystemInfo — the filesystem dates, not upload dates), extension, and the hash. The scan row records platform='cloud', the drive id as the volume serial, owner as the drive name, and quota as disk totals. The deltaLink lands in a small cloud_state table keyed by drive id.
main(argv) Token-source precedence (file > paste > device-code), then crawl → build → the same summary .txt every census gets. Default catalog name follows the census_onedrive_… convention beside the script.

3 · Pseudo-code: the whole program on one screen

main:
    provider = first available of:
        --token-file  -> read file (tool never writes it); renew = re-read after prompt
        --paste-token -> getpass (hidden); renew = ask again
        otherwise     -> device-code sign-in (Files.Read, no refresh token);
                         renew = run the flow again
    print describe_token(provider.token)      # who / scopes / expiry — never the token

crawl:
    drive = GET /me/drive ($select: id, driveType, owner, quota)
    url = /me/drive/root/delta?$select=id,name,size,parentReference,
                                       file,folder,fileSystemInfo,root,package&$top=999
    while url:
        page = fetch(url)                     # see fetch below
        for item in page.value:
            items[item.id] = compact(item)    # ~300 B record; raw dict dropped;
        url = page.nextLink                   #   duplicate ids: last occurrence wins
    deltaLink = page.deltaLink                # resume cursor for next time

fetch(url):
    refuse unless url starts with https://graph.microsoft.com/   # token cannot leave Graph
    GET with Authorization: Bearer <token>    # the ONLY authenticated line
    on 429/503/504: sleep Retry-After, retry (bounded)
    on 401: provider.renew(); retry the SAME url once   # crawl resumes in place

build_catalog:
    children[parent id] += item;  root = the item with the root facet
    walk top-down from root assigning entry ids and depths, flush rows every 5,000
        folder or package -> dir row (packages = OneNote notebooks, walked like folders)
        file   -> file row + size + ext + quickXorHash into entry.hash
        parent never seen, or parent is a file -> attach under root, print a note
    scan row: drive='onedrive:<owner>', platform='cloud',
              serial = drive id, disk totals = quota
    store deltaLink in cloud_state;  write the standard summary .txt

4 · The safety model — audited, with the honest limits

Claims about the tool (each verified by reading the code and by unit tests, not asserted from intent):

GuaranteeWhy it holds
read-only, twice over Every Graph request is a GET; the only POSTs are the sign-in handshake at login.microsoftonline.com. Independently, the server enforces the token's scopes — the tool could not write even if it tried with a read-only token.
no content, no hydration The $select excludes downloadUrl, so responses never even contain a link to file content; and the local filesystem is never touched, so cloud placeholders cannot hydrate. Nothing is downloaded — hashes come precomputed.
token goes one place A single line attaches the credential, and fetch_json refuses any URL outside graph.microsoft.com before building a request — a tampered next-link could not steer the token elsewhere. Tested against a hostile URL.
token is never persisted The only open() on the token path is read-mode. Nothing writes it; error paths print server responses and status codes, never request headers; describe_token output is unit-tested to not contain it. The command line carries only a file path, so process listings reveal nothing, and --paste-token uses hidden input so the console scrollback stays clean.
no supply chain Standard library only, ~400 lines, one file — auditable in a sitting, and the public repo history shows exactly what runs.
what does persist The catalog (filenames, sizes, dates, hashes — sensitive the way every census catalog is; gitignored) and the deltaLink cursor, which is a resume position, not a credential.

Honest limits — the risks that live around the token, not in the code:

  • A borrowed Graph Explorer token carries Graph Explorer's full consented scopes — likely more than Files.Read. This tool only reads metadata, but the token itself is a ~1-hour capability for anything those scopes allow, in anyone's hands. Expiry is the backstop: signing out of Graph Explorer does not revoke already-issued tokens.
  • The clipboard is the sneakiest copy. With Windows clipboard history enabled (Win+V), the copied token sits in it after you paste. Clear it when done.
  • The token file is your custody. Keep it out of repos and synced folders (a token synced to OneDrive by OneDrive would be a poetic failure), delete it after the run; the repo's .gitignore blocks token.txt/*.token as a backstop.
  • Process memory is not scrubbable. Python strings live in the heap until exit; a crash dump or swap could theoretically expose the token during its lifetime. Bounded by the short process life and the token's own expiry.
  • Nothing defends a compromised machine. Anything running as you can do what you can do.
The four-minute ritual: copy the token → save to %TEMP%\token.txt (never a synced folder) → run the crawl → delete the file → clear clipboard history. A one-hour credential, handled for minutes, exercised through a single pinned, read-only, audit-visible request path.
